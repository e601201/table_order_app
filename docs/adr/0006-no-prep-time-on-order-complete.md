# 注文完了画面は調理時間を表示しない（目安を約束する根拠がない）

注文完了画面（`orders/OrderComplete`、`注文完了`）は `Checkout` 直後に客へ表示される。この画面では調理時間（「調理時間の目安」）を表示しない。従来ハードコードされていた「10〜15分」カードは削除した。

> **Amendment（ADR-0007）**: 旧版は「調理は会計後に始まる」（先会計）を前提に「会計より前のこの画面で時間を出すのは嘘になる」と論じていた。正典フローは**後会計（テーブルサービス）**で確定し、調理は `OrderPlaced` 直後にキッチンが着手する（会計は最後）。よって「会計前だから調理ゼロ」という旧根拠は撤回する。結論（この画面に調理目安を出さない）は、`prep_time` データの不在とキッチン待ち行列の不可測という別の根拠で維持する。

後会計では調理は `OrderPlaced` 直後に始まり、料理はお席まで運ばれる。それでもこの画面で着丁目安を出せないのは、提供までの時間を予測する材料がこの画面に無いからだ。`MenuItem` に `prep_time` データは存在せず、キッチンの待ち行列（同時調理数・バックログ）やテーブルサービスの巡回も画面からは読めない。出せばどれも根拠のない数字になる。

## Considered Options

- **メニュー別 prep time から目安を算出して出す** — 却下。`MenuItem` に prep time データが存在しない。仮にあっても、提供時間はキッチンの待ち行列とテーブルサービスの巡回に支配され、その時点の店内状況を画面は知り得ない。固定値も平均値も「もうすぐできる」という時間軸の嘘になる。
- **レジ端末（`cashier/payment_complete`）に目安を出す** — 却下。あれは Cashier 向けのスタッフ端末で、客は見ない。客向けの置き場所にはならない。
- **目安を出さず、調理時間を約束しない** — 採用。後会計の正直な案内（「お料理ができ次第お席までお持ちします。お会計はお食事後にレジで」）だけを置き、時間は約束しない。

## Consequences

- `OrderComplete.tsx` から Prep Time カードと未使用の `Clock` import を削除。props・コントローラ・型は調理時間を持たないため変更なし。
- 完了画面フッターは後会計の案内に揃えた（先会計コピー「お支払い確認後に調理を開始します」は撤去。ADR-0007）。
- 客向けの調理目安（ETA）を将来出すには、(1) `MenuItem` の prep time データと (2) 提供時間を推定できる材料（キッチン待ち行列の可視化など）が必要で、どちらも現状スコープ外。`cashier/payment_complete` はスタッフ端末なので流用できない。
- この原則は CONTEXT.md の "Flagged ambiguities" にも記載。`注文完了` という名前は `完了` の多義（`提供済み` / `お支払い完了` とは別）の一例であり、調理の完了を意味しない。
