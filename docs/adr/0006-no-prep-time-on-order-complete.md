# 注文完了画面は調理時間を表示しない（会計前に調理は始まらない）

注文完了画面（`orders/OrderComplete`、`注文完了`）は `Checkout` 直後・**会計より前**に客へ表示される。料理が作られるのは kitchen progress 軸の `In progress → Ready` 区間で、その開始は「お支払い確認後」。したがってこの画面では調理時間（「調理時間の目安」）を表示しない。従来ハードコードされていた「10〜15分」カードは削除した。

## Considered Options

- **メニュー別 prep time から正確な目安を算出してこの画面に出す** — 却下。仮に値が正確でも、客がこの画面を見ている時点で調理は1秒も始まっておらず、レジまでの移動・会計待ち行列・会計・キッチンの待ち行列という、可変で店側が予測できない空白を必ず含む。「もうすぐできる」という時間軸の嘘になる。加えて `MenuItem` に prep time データは存在しない。
- **レジ端末（`cashier/payment_complete`）に目安を出す** — 却下。あれは Cashier 向けのスタッフ端末で、客は見ない。客向けの置き場所にはならない。
- **カードを削除し、調理時間を約束しない** — 採用。画面下部の「お支払い確認後に調理を開始します」が唯一の正直な時間案内であり、これだけで画面は内部的に一貫する。

## Consequences

- `OrderComplete.tsx` から Prep Time カードと未使用の `Clock` import を削除。props・コントローラ・型は調理時間を持たないため変更なし。
- 客向けの調理目安（ETA）を将来出すには、(1) `MenuItem` の prep time データと (2) **支払い後の客向け画面**（現状存在しない）の両方が必要で、どちらも現状スコープ外。`cashier/payment_complete` はスタッフ端末なので流用できない。
- この原則は CONTEXT.md の "Flagged ambiguities" にも記載。`注文完了` という名前は `完了` の多義（`提供済み` / `お支払い完了` とは別）の一例であり、調理の完了を意味しない。
